## 3. Defects found on device and fixed

Both were found by running the app on the emulator, and neither was reachable from a unit
test: both are layout behaviours that only exist once the UI is measured on a real device.

### 3.1 Every subdivision screen crashed on a fresh install

`SubdivisionNotice` — the empty and unavailable state — carried its own
`Modifier.verticalScroll`, and it is used as the empty state **inside `LazyColumn`
items**. A lazy list measures its items with unbounded height, so the screen threw:

```
java.lang.IllegalStateException: Vertically scrollable component was measured with an
infinity maximum height constraints, which is disallowed.
```

An empty list is the default state of a fresh install, so **Subdivision review, Stations,
Staff and Matters all crashed the moment they opened**. Four of the five acceptance tests
failed on this before the fix; they pass after it.

Fix: the in-list notice no longer owns a scroll container, and a new
`SubdivisionNoticeScreen` carries one for notices that occupy a whole destination
(`SubdivisionComponents.kt`). Evidence: `logs/subdivision-e2e-run1.log` (before),
`logs/subdivision-e2e-run4.log` (after).

### 3.2 The primary action sat under the system navigation bar

`SubdivisionScaffold` set `contentWindowInsets = WindowInsets(0)` and never compensated.
These destinations fill the screen and carry no bottom navigation bar of their own, so the
last row of a list rendered **under the gesture navigation bar**, where taps go to the
system rather than the app. On the review screen that last row is the primary
`Record review` action.

Fix: the scaffold now applies
`WindowInsets.navigationBars.only(WindowInsetsSides.Bottom)`, so all six destinations keep
their content clear of the navigation bar. This matches `DESIGN.md` ("Preserve system
back, keyboard and navigation insets"). Confirmed visually — compare
`frames/f22.png` (button flush against the gesture pill) with
`frames/g24.png` and `screenshots/ui-review/subdivision-20-review-populated-manual.png`
(button clear of it).

Neither fix changed the unit suite's count, because neither behaviour is observable from a
Robolectric test; the device tests are the regression cover.

## 4. Device acceptance and visual QA

**Device:** task-owned emulator `emulator-5596`, AVD `kaavalan-contact-import-20260909`,
Android **14**, API **34**, `arm64-v8a`, isolated package `com.kaavalan.note.debug.officer`.
The public `com.kaavalan.note` package (a prior signed release with synthetic data) was
left installed and untouched throughout.

**How the suite was driven.** The Gradle device-test task could not be used even with
`ANDROID_SERIAL=emulator-5596` set as the handover requires: ddmlib enumerates every
attached device and hung indefinitely fetching properties from an unrelated
`emulator-5680` on this host. The suite was therefore driven directly through
`adb -s emulator-5596` using **the same AndroidX Test Orchestrator with
`clearPackageData true`** that the Gradle task would have used, so each test still got a
fresh app state. Only the task-owned emulator was touched.

### `SubdivisionCrmEndToEndTest` — 4 of 5 pass

| Scenario | Result |
|---|---|
| `everyTabOffersItsSubdivisionEntry_andEachDestinationOpensAndReturns` | **pass** |
| `theSubdivisionEntriesAreHiddenInThePrivateWorkspace` | **pass** |
| `anArchiveBlockedByOpenWork_explainsTheNextActionInline` | **pass** |
| `changeWorkContextFromInstructionDetail_journalsBothSidesAndSurvivesRecreation` | **pass** |
| `setUpSubdivision_addStation_markStaff_addMatter_captureInContext_thenRecordReview` | **fails at its final step** — see below |

Latest full run: `logs/subdivision-e2e-run16.log`.

**The one failure, stated precisely.** The test completes and asserts, against the real
database: profile setup; station creation; classifying a contact as staff with a station
and responsibilities (`isStaff`, `staffActive`, `responsibilities`, non-null `stationId`);
matter creation; capture opened from the matter with the context preselected, and the saved
instruction carrying the matter's `matterId` and the station's `stationId`; and the review
screen rendering with the correct counts, all five filters, and the honest
"No earlier review for this scope" state. It then fails waiting for the `Record review`
editor to open after the injected click.

**This is a test-harness limitation, not a product defect, and that was verified rather
than assumed.** Driving the identical button with a raw `adb -s emulator-5596 shell input
tap` opens the editor correctly, with the right scope, the right counts and the correct
"These counts are stored with the note as a record of this moment" wording — see
`screenshots/ui-review/subdivision-21-review-editor-manual.png`. Compose's injected click
lands while this software-rendered device is still laying the lazy list out. Three
remedies were tried and are retained because each is independently correct — scrolling the
lazy list itself rather than the node, waiting for idle plus a settle delay, and raising
Espresso's idling timeouts to five minutes — but none made the injected click reliable
here. The behaviour behind the button is covered by
`SubdivisionRepositoryTest` ("a review stores the counts that were true at save time and
completes nothing", "review counts are scoped and never include hidden or sensitive
records") and `SubdivisionViewModelTest` ("recording a review stores the counts and
reports success").

This is an open item. It is **not** claimed as passing.

### Device stability, recorded honestly

This host cannot give the emulator hardware rendering — `Software GL rendering will be used
due to system memory pressure (Available Memory: 1073 MB, Required: 5120 MB)` — and during
the session the suite also produced, on different runs, an instrumentation process that
died before starting a test and `No compose hierarchies found in the app` (the Activity
never launching). Rebooting the emulator cleared those. They are environment symptoms, not
product results, and no test was marked passing on the strength of a run that showed them.

`subdivisionRecord_atOneAndAHalfTimesSystemFont_staysReachable` **passes**: at 1.5× the
