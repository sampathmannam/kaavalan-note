# KaavalanNote v2.7.6 — Instruction provenance

versionCode: 59
versionName: 2.7.6

## What changed

- A **For me** instruction can now separately record who assigned it. This no longer
  overloads the contact responsible for or related to the work.
- Common senior-officer choices — **SP**, **DIG**, **ADG**, **DGP** and **CCA** — are
  available as one-tap options. Any other name or designation can be typed, and an
  existing contact can be selected when the exact officer is already in the roster.
- The assigning officer is shown on instruction cards and in the detail sheet, remains
  editable, and is included in instruction search.
- Draft recovery retains the choice across process recreation. Changing responsibility
  away from **For me** clears the hidden issuer so stale provenance cannot be saved.
- Contact-backed issuers retain both the optional contact link and a historical display
  snapshot, so a later rename or transfer does not erase who issued the instruction.

Package `com.kaavalan.note` and the pinned production signing identity are unchanged.
Room schema advances from 18 to 19 and manual-backup schema from 4 to 5. Both upgrades
are backward compatible: existing instructions receive null issuer fields, and backups
from earlier supported versions continue to restore.

## Verification

- All 906 JVM tests pass with no failures, errors or skips, including capture draft,
  repository persistence, database migration and backup round-trip coverage for the new
  issuer fields.
- Android lint passes with no errors or fatals; debug and R8-optimized signed release
  variants assemble.
- The v18 → v19 upgrade and the new capture interaction were exercised on a connected
  Motorola Signature running Android 17/API 37. SP selection populated the issuer field,
  and no Room, SQLite or application fatal was recorded.
- The signed universal APK is verified against the existing pinned certificate before
  publication, and the release gate rejects a non-increasing version code or unsigned
  artifact.

Install as an in-place update through the existing Obtainium entry or the signed universal
APK. Do not uninstall the current app: Android preserves the encrypted local database only
when the update is installed over the existing package with the same signing identity.
