# KaavalanNote v2.3.0 — Focus first

**Release date:** 2026-09-07
**versionCode:** 48
**Upgrade path:** direct update from v2.2.0 (`com.kaavalan.note`); existing local data is preserved

## What changed

- **One next action on Today.** The screen now starts with one **Start here** instruction selected from the existing brief order. Remaining needs, waiting items and carried items follow; summaries and reflection tools come afterward.
- **A clearer People directory.** People is named consistently in navigation, the add-person action moves to the header, and the note bar remains the only large creation control. Person rows retain readable open counts and quiet-follow-up accessibility descriptions.
- **Capture works before setup.** A raw note can be saved with `personId = null`; adding a person is useful organisation, never a prerequisite that can discard the first thought.
- **Reliable Android ingress.** Shared text, guarded shared-image OCR, widget capture and quick-settings capture all feed the activity-owned `RootViewModel` instance consumed by the visible Home capture sheet. One-shot events are cleared after consumption.
- **Visible Settings state.** The Settings navigation item remains selected while its configuration sheet is open.
- **Post-v2.2 reliability line included.** This release also carries the green release-build/device-test pipeline, startup and migration hardening, pre-Android-13 voice fix, automatic Drive-backup restore compatibility, and retention cleanup for historical outbox note text.

## Architecture and privacy

The redesign adds no database migration, analytics, telemetry, live sync, or remote inference. SQLCipher Room remains the working store. Google Drive backup remains optional and encrypted on-device; Android system speech recognition retains its documented device-dependent privacy boundary.

## Release gates

The release is publishable only after GitHub CI passes unit tests, Android lint, debug assembly, R8 release assembly and connected-device instrumentation. The signed Obtainium APK must also pass the repository's signing-certificate fingerprint check in `release.sh`.
